# 方法论经验与踩坑 (LESSONS)

> 本文档诚实记录 RSP-FT 实验中发现并修正的方法论问题。我们相信，一个经得起推敲的实验，恰恰体现在它如何发现并排除混淆变量。分享这些经验，供后续研究者避坑。

---

## 一、结论层面的经验

### 1. 操纵检验（manipulation check）不可省

我们用离散分组 A/B/C 操纵"反问强度/质量"，并假设 C（黄金三问）> B（普通反问）。但用裁判 M 值做操纵检验后发现：**古诗词操纵成功（C 组 M 更高），菜谱操纵失败（C 组 M 反低于 B）**——菜谱的"黄金三问"固定模板过于通用（"核心食材起何作用"套用所有菜），不如数据集中针对具体菜品的反问精准。

**教训**：离散分组是否真正操纵了目标变量，必须用独立测量验证。若不做操纵检验，会把"操纵失败"误读为"处理无效"。

### 2. 当操纵被污染，回归连续变量

分组被污染后，我们抛开 A/B/C 标签，直接以连续反问质量 M 对回答质量 Y 回归——三个数据集均显示稳健正相关（r=0.25–0.46）。**被离散分组掩盖的真实关系，在连续变量上清晰显现。**

**教训**：离散分组便于叙事，但当操纵不干净时，连续测量更接近真相。

### 3. 长度是生成式任务中易被忽略的混淆

反问训练使答案变长（副作用），而过长答案被裁判惩罚（长度与 Y 负相关）。控制长度后，组间格局显著改变（相同长度档内反问组反而更优）。**"处理有害"的表象，部分源于处理的长度副作用，而非处理内容本身。**

**教训**：比较不同处理的生成质量时，务必检查并控制答案长度这一混淆。

### 4. 只看均值会误判，务必用统计检验

多组均值差异（如 3.69 vs 3.21）看似明显，但配对检验显示大多不显著（p>0.5）——是噪声。我们曾差点据均值下"倒 U 型"结论，统计检验及时拦截。

**教训**：组间比较必须用配对检验 + 效应量（Cohen's d），不能仅凭均值。

### 5. 训练 loss ≠ 任务质量

训练 loss 低不代表回答质量高。例如"黄金三问"因模板规整而 loss 低，但不意味回答更好。且组间 loss 不可横向比较（多段损失 vs 单段）。

**教训**：结论只认下游评测指标，训练 loss 仅作过程参考。

## 二、工程层面的经验

### 6. LoRA 模型加载后需显式启用梯度

`AutoModelForCausalLM.from_pretrained` 加载 LoRA adapter 后默认推理模式，`requires_grad=False`，导致 `loss.backward()` 报 "element 0 does not require grad"。需显式 `requires_grad_(True)` 并加自检（可训练参数数>0）。

### 7. API 调用必须设超时

M_A 补充、裁判评分等 API 调用若不设 `timeout`，单个请求挂起会导致整个流程僵死。务必设超时 + 指数退避重试 + 失败回退。

### 8. 生成加速：预生成缓存 + 批量生成

self-play 的瓶颈是"逐 token 生成"和"串行 API 等待"，GPU 利用率可低至 12%（隐形亏损）。两级优化：
- **预生成缓存**：训练前批量并发生成 M_A 补充并缓存，训练时查表零等待（与实时生成在 M_A 冻结假设下等价）。
- **批量生成**：将逐条生成改为大 batch（左 padding），GPU 利用率 12%→68%，速度提升数倍。

### 9. `apply_chat_template` 返回类型兼容

新版 transformers 的 `apply_chat_template(tokenize=True)` 可能返回 `BatchEncoding` 而非 list/tensor，需统一归一化处理，否则报类型错误。

## 三、研究过程的真实性

我们保留了一个真实插曲作为过程诚实性的佐证：分析菜谱数据得到"黄金三问质量低于数据集反问"后，研究者凭记忆质疑"古诗词好像相反"，回查原始数据确认古诗词确为 C>B，从而将结论从"黄金三问普遍不佳"修正为"操纵有效性因领域而异"。**不轻信单一领域结论、反复核对原始数据、人在回路把关**——这些是本工作可信度的基础。

---

## 四、一句话总结

反问式训练"是否有效"不是一个二元问题，而是"在何种质量、长度、训练强度、模型容量与评价标准下有效"的条件性问题。我们通过操纵检验、连续变量分析、混淆控制与统计检验，尽力把这些条件一一厘清。相关代码与数据开源，欢迎复现与质疑。
